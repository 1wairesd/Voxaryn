# p2-speculation.md — Эксперимент: спекулятивный параллелизм внутри одного острова

> Минимальный эксперимент P2 из [p2-feasibility.md](p2-feasibility.md) §6.
> Он **не встроен в игровой цикл**: работает как тень последовательного
> прохода. Код `game/speculate.rs` и `mobs/spec_probe.rs` собирается только
> с фичей `p2-speculate` и включается `HORIZON_P2_SPECULATE=1`. Мир всегда
> получает результат обычного `mob_pass`; эксперимент считает свой вариант на
> копиях и сравнивает. Все числа — 2026-11-08, i5-12400F 6/12, Windows 11,
> бинарник `.local/baseline/horizon-client-p2-spec.exe`. Сырые данные
> (не в Git): `.local/voxaryn-bench/p2_threads.json`, `p2_density.json`,
> `p2_pile.json`, `p2_groups*.json`.

## 1. Что делает эксперимент

1. **Фаза 1 (параллельно, пул rayon).** Каждый моб тикает на своей копии
   против снимка начала тика, как будто ни один моб до него не двигался.
   Зонд (`spec_probe`) записывает, что тик прочитал у других мобов:
   - ответ push-запроса: кого толкнул, в каком порядке, по каким позициям;
   - число всех прочих чтений (`others_near`, `seen`; через них идут
     `nearby`, `target_info` и цели).
2. **Фаза 2 (последовательно, в порядке мобов, по настоящему прогрессивному
   состоянию).** Спекулятивный тик моба *k* принимается, только если его
   входы совпадают с теми, что даёт последовательный проход:
   - (а) никакой толчок от мобов < *k* его не ждёт (`pending`);
   - (б) других чтений не было (`reads`);
   - (в) push-запрос, заданный заново настоящему снимку (в нём мобы < *k*
     уже на итоговых местах), даёт **тот же** список (`targets`);
   - (г) level random не тронут, событий на других мобов (размножение) нет.

   Иначе моб *k* **пересчитывается** с оригинала против настоящего
   состояния, ровно как в `mob_pass`.
3. **Сверка с последовательным проходом.**
   - на каждом проходе: позиции, скорости и здоровье всех мобов (побитно),
     события, события гостей, привязки, мёртвые;
   - на каждом 10-м: полный `Debug` каждого моба.

**Транзитивные зависимости.** Проверка (в) читает настоящее состояние в
порядке мобов. Если моб *j* пересчитан и встал в другое место, каждый
следующий моб проверяется уже против нового *j*. Ошибка не может «протечь»
через принятого соседа. Счётчики:
- `cascades` — отказ из-за соседа, который сам был пересчитан;
- `accepted_after_recompute` — принят, хотя среди соседей был пересчитанный.

Финальная сверка с последовательным проходом проверяет всю цепочку целиком.

Ограничения эксперимента: только коровы, грибные коровы, свиньи, овцы, куры
(их цели читают других мобов только через `others_near`/`seen`); без
наездников и поводков; без влюблённых. Иначе проход пропускается и
пропуск учитывается.

## 2. Корректность

**Во всех прогонах результат побайтно совпал с последовательным.**
- дешёвая сверка: 3 200 из 3 200 проходов;
- полная: 320 из 320 (`cheap`/`deep` в SPECSTATS).

Прочих чтений (`reads`) не было ни разу: для этих видов в этих состояниях
push-запрос — единственное чтение других мобов. Это подтверждено зондом, а не
только аудитом.

## 3. Результаты

копирование, сверка). `seq` — настоящий последовательный проход того же тика.
`spec` = копирование + фаза 1 + фаза 2. Средние по ~300 проходам на прогон.

## 4. Частота конфликтов против стоимости повторов

Отказы делятся на два вида.
- **`pending`** — моба уже толкнул кто-то раньше в этом тике. Это
  настоящая зависимость, а не неточность проверки.
- **`targets`** — список соседей при пересчёте другой: сосед < *k* сдвинулся
  и стал/перестал касаться.

Оба растут с плотностью контактов. Цена прохода раскладывается так:

`spec ≈ clone (1.7) + фаза1 (≈ seq × раздувание / потоки) + проверка (≈ 3.0–3.4) + пересчёт (≈ доля откатов × seq)`

| часть | загон | куча | замечание |
|---|---:|---:|---|
| копия всех мобов | 1.7 мс | 1.7 мс | плата за возможность отката; не зависит от числа откатов |
| проверка в фазе 2 (без пересчёта) | 3.0–3.4 мс | 26 мс | повтор push-запроса + `seen` + сетка + бухгалтерия толчков, **последовательно**, даже при 100 % принятых |
| пересчёт | 0.6–1.5 мс | 27 мс | ≈ доля откатов × seq |

Даже при 100 % принятых и бесконечном числе ядер:

`spec ≥ clone + проверка ≈ 1.7 + 3.0 = 4.7 мс` против seq ≈ 10.6 мс

Потолок ≈ ×2.2 для этого загона. С измеренным раздуванием на 6 потоках —
не больше ×1.4. Получено ×1.03–1.13. Точка безубыточности по откатам —
около 10 %: при 4 % (`herds_8x250`) выигрыш 13 %, при 11 % (загон) уже 3 %,
при 35 % проигрыш 23 %.

**Вывод по эксперименту.** Спекуляция внутри острова корректна и
переносит транзитивные зависимости, но в реальной ферме даёт не больше
~×1.1 на 6 потоках. Как только откатов больше ~10 %, она медленнее
последовательного прохода. Дорогие части — полная копия мобов и
последовательная проверка, — неизбежны в этой схеме. По критерию задания
(«медленнее или слишком дорогая система откатов») результат фиксируется:
**как основной путь P2 спекуляция не годится**.

## 5. Альтернатива: острова по доказанному контакту

Тот же зонд показал, что у этих видов (взрослые, не влюблённые) других
чтений нет: соседи читаются только через толкание. Значит, «радиус
досягаемости» такого моба — не follow range (27 блоков), а **возможный
контакт за тик**. Это боксы на расстоянии ≤ доказанного шага S (P1.2,
`islands::motion_step`).

Если строить острова по графу «может коснуться за этот тик», без копий,
спекуляции и проверки, загон мог бы распасться на независимые группы, и их
можно было бы тикать параллельно механизмом P1. Эксперимент считает этот
граф тремя способами (`p2_groups*.json`, `p2_fixed.json`):

- при **доказанном** шаге P1.2;
- при шаге, который тик **на самом деле** сделал (оракул: не доказательство,
  а верхняя оценка потенциала);
- при фиксированных шагах 0.3 / 0.5 / 0.8 блока.

### 5.1 Группы контакта

| Сцена | доказанный шаг → крупнейшая группа | фактический шаг → групп / крупнейшая | 0.3 → групп / крупн. | 0.5 | 0.8 |
|---|---|---|---|---|---|
| `herds_8x250` (250 в загоне) | 1.29–1.31 → 244–246 | 0.135–0.149 → 985–1057 / **36–39** | 555 / 69 | 343 / 95 | 165 / 168 |
| `pen_2000_mid` (2000 в 64×64) | 1.64–1.66 → **2000** | 0.153–0.165 → 311–393 / **419–435** | 88 / **1619** | 25 / 1937 | 9 / 1987 |
| `herds_1x1000_7x100` | не доказан | 0.28 → 399 / 999 | 386 / 999 | — / 1000 | — / 1000 |
| `pen_2000_tight` | не доказан | 0.27 → 1 / 2000 | 1 / 2000 | 1 / 2000 | 1 / 2000 |
| `cows_2000` (куча) | не доказан | 0 → 1 / 2000 | — | — | — |

Выводы:

1. **Доказанный шаг в ~10 раз больше фактического** (1.3–1.7 против
   0.14–0.17 блока). Доказательство берёт худший случай для каждого моба:
   любая корова может побежать с `Panic(2.0)`, любой сосед может толкнуть.
   При таком шаге граф контакта — один остров на загон.
2. Даже при **идеальном** знании фактического шага большой загон делится
   плохо: крупнейшая группа — 21 % стада. Потолок распараллеливания ≈ ×4.7 до
   раздувания и накладных расходов.
3. **Граница перколяции очень близко.** Уже при шаге 0.3 (в 2 раза больше
   фактического) крупнейшая группа — 81 % стада, при 0.5 — 97 %. Чтобы
   альтернатива работала, доказательство должно попадать в фактическое
   движение с точностью ~20 %. Это практически означает знать результат тика
   до тика. Для этого нужна именно спекуляция, а она (§4) дорога.
4. Где острова и так мелкие (загоны P1), граф контакта дробит их ещё
   мельче. Но P1 их уже параллелит, и выигрыш упирается не в число
   островов (p1-overhead §2–§3).

**Альтернатива «острова по контакту» тоже не даёт параллелизма внутри
плотной фермы.** Причина не в реализации, а в геометрии: при плотности
≥ 0.5 моба на блок² граф «может коснуться» перколирует при любом
доказуемом шаге.

## 6. Что из этого следует для P2

Измерено, а не предположено:

| Подход к одному плотному острову | Корректность | Результат на 6 потоках | Почему |
|---|---|---|---|
| Спекуляция + проверка в порядке + пересчёт (этот эксперимент) | побайтно, транзитивно (3200/3200, 320/320) | ×1.13 (редкий загон), ×1.03 (плотный), < 1 при ≥ ~10 % откатов | копия всех мобов 1.7 мс + последовательная проверка 3 мс; откаты `pending` — настоящие зависимости |
| Чистые фазы (`base_tick` + `server_ai_step` параллельно) | требует перестройки `Mob::tick` | потолок < ×1.15 | 12–14 % тика (p2-feasibility §5.1) |
| Острова по доказанному контакту | доказуемо | 0: один остров | доказанный шаг в 10× больше фактического; перколяция уже при 0.3 блока |
| Поиск соседей | — | ≤ 8 % в куче | не узкое место (p2-feasibility §4) |

**Рекомендация.** Не делать P2 как «многопоточность внутри одного острова
мобов». Все три варианта упираются в одно: в плотной группе зависимости
настоящие, а не следствие консервативного плана. В тесной группе 63 % мобов
читают соседа, уже сдвинувшегося в этом тике (P1.1); здесь 60 % откатов —
толчки от ранее тикнувших мобов. Дешёвой точной границы нет.

Направления, где у многопоточности есть пространство, по измерениям P1/P1.1:

1. **Параллельность между фазами тика.** Вне прохода мобов остаётся
   4.7–6.9 мс последовательного тика (p1-overhead §2.1, p1-benchmarks
   §2.1):
   - блоки и случайные тики;
   - жидкости;
   - трекинг сущностей и сетевая сериализация;
   - снаряды и смерти.

   Следующий шаг исследования — аудит зависимостей этих фаз друг от друга
   и от прохода мобов (что читает и пишет каждая), по той же методике:
   консервативный план, сверка с последовательным результатом, негативные
   тесты.
2. **Острова P1 шире.** Больше проверенных видов (летучая мышь, лиса —
   сейчас они чаще всего держат сцены P0 последовательными), меньше
   накладных расходов: копия 0.8 мс, split/merge 1.3 мс, раздувание работы
   ×1.75 (p1-overhead §2, причина не установлена).
3. **Для плотных куч** выигрыш однопоточный: бухгалтерия 4 млн толчков —
   ~12 мс вне `mob_tick` в `cows_2000`. Это не многопоточность, и делать
   это стоит отдельной задачей, если такие сцены важны.

Эксперимент оставлен в дереве за фичей `p2-speculate` (по умолчанию
выключена, в игровой цикл не встроен: результат мира — всегда
последовательный), чтобы его можно было повторить
(`tools/voxaryn/README.md`).
